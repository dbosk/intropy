\section{Research Context}
Research question: Is avoiding duplicated code (the DRY principle,
``Don't Repeat Yourself'') beneficial -- that is, is duplicated code a
maintenance and fault risk -- and does the principle originate with Hunt
and Thomas, The Pragmatic Programmer (1999)?

A paper is RELEVANT if it reports evidence about code clones or
duplicated source code and faults, maintenance effort, stability, or
deliberate/intentional cloning, or if it is about the DRY principle
itself (its origin, formulation, or criticism).

Assign exactly one of these four category tags:

\begin{itemize}
\item
  supports-claim: bears on the claim AND supports that duplication is a
  risk. Empirical or review evidence that cloned/duplicated code is
  fault-prone, that inconsistent changes to clones cause bugs, that late
  propagation is harmful, that duplication increases maintenance effort
  or defect density, or that removing duplication improves quality.
\item
  qualifies-claim: bears on the claim BUT contradicts or narrows it.
  Evidence that clones are beneficial, principled, deliberate,
  tolerated, harmless, long-lived without harm, or MORE stable / less
  often changed than non-cloned code; evidence that the harm of clones
  is small, unproven or context-dependent; criticism of DRY as too rigid
  or dogmatic; duplication used deliberately for performance,
  readability or optimisation.
\item
  adjacent-subtopic: software-engineering work on code clones or
  duplication that has NO bearing on whether duplication is harmful.
  Clone detection algorithms, detection tools, benchmarks,
  machine-learning clone search, surveys of detection techniques, clone
  visualisation, clone refactoring tooling, code-similarity/plagiarism
  detection, malware or app clone detection, dataset duplication and
  data leakage in language models.
\item
  off-topic-false-hit: not about duplication in human-written source
  code at all. Biological or molecular cloning, medicine, genetics,
  agriculture, wireless-sensor node replication attacks,
  hardware/circuit deduplication, or any unrelated use of the words
  ``clone'', ``dry'' or ``duplication''.
\end{itemize}
