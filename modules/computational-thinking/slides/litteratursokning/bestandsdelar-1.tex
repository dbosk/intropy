\begin{abstract}
Research question: Does an algorithm decompose into the parts sequence and execution order, variables and state, selection, repetition, and functions -- and does the literature support that decomposition? This track covers structured programming theory (the structured program theorem: any flowchart-expressible computation reduces to sequence, selection and iteration) and empirical work on what novice programmers misunderstand about exactly those parts (execution order, state and variables, conditionals, loops, tracing). A paper is relevant if it says something about which control constructs a program is built from, about how novices misunderstand those constructs, or about the theoretical adequacy of that set of constructs. Category tags to assign exactly one of: supports-claim = the paper bears on the claim and supports it; qualifies-claim = the paper bears on the claim but contradicts, narrows or complicates it; adjacent-subtopic = same field, different question; off-topic-false-hit = another field, keyword overlap only. The search covered scopus and yielded 1053 papers (242 kept, 811 discarded, 0 pending).
\end{abstract}
