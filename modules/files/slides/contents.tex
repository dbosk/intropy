  \end{itemize}

  \textbf{Pedagogisk sekvens}: Parallella definitioner (overlay 1-3) skapar

Innan vi lär oss hur vi arbetar med filer i Python behöver vi förstå \emph{varför}
filer existerar och vad de fyller för funktion i ett datorsystem. Detta handlar
om skillnaden mellan två fundamentalt olika typer av minne i datorn.

\subsection{Primärminne och sekundärminne}

När ett Python-program körs finns alla variabler och data i datorns
\emph{primärminne} (även kallat RAM eller arbetsminne). Detta minne är mycket
snabbt --- åtkomsttider mäts i nanosekunder --- vilket gör att programmet kan
arbeta effektivt med data. Men primärminnet har en avgörande begränsning: det
är \emph{flyktigt}. När programmet avslutas, eller när datorn stängs av,
försvinner allt innehåll i primärminnet.

Detta skapar ett problem: Hur kan vi \emph{bevara} data mellan programkörningar?
Hur kan vi \emph{dela} data mellan olika program? Hur kan vi hantera
\emph{större} mängder data än vad som får plats i primärminnet?

Svaret är \emph{sekundärminne} --- oflyktigt lagringsutrymme som bevarar
information även när datorn är avstängd. Detta kan vara en hårddisk, SSD, eller
annan lagringsmedia. Sekundärminnet är långsammare än primärminnet (åtkomsttider
i mikro- till millisekunder), men det är persistent och kan lagra mycket större
mängder data.

\begin{frame}
  \begin{definition}<1,3>[Primärminne]
    \begin{itemize}
      \item Datorns arbetsminne.
      \item Exekverande program (processer) och data (variabler) lagras här.
      \item Flyktigt minne.
      \item Snabbt: storleksordning nanosekunder.
    \end{itemize}
  \end{definition}

  \begin{definition}<2,3>[Sekundärminne]
    \begin{itemize}
      \item Långsammare minne: storleksordning mikro- till millisekunder.
      \item Oflyktigt.
      \item Icke-exekverande program och data (filer) lagras här.
    \end{itemize}
  \end{definition}
\end{frame}

\subsection{Vad är en fil?}

En \emph{fil} är en namngiven samling data som lagras i sekundärminnet. Vi har
alla erfarenhet av filer från vår dagliga datoranvändning: Python-program
(\texttt{.py}-filer), bilder (\texttt{.jpg}, \texttt{.png}), dokument
(\texttt{.pdf}, \texttt{.docx}), och så vidare. Faktum är att de
Python-program vi skriver själva är lagrade som textfiler på hårddisken.

\begin{frame}
  \begin{block}{Filer}
    \begin{itemize}
      \item Vi har erfarenhet av filer.
      \item Våra program är sparade i filer.
    \end{itemize}
  \end{block}

  \pause

  \begin{example}
    \begin{itemize}
      \item Pythonprogram,
      \item bilder,
      \item dokument,
      \item \etc
    \end{itemize}
  \end{example}
\end{frame}

Men varför behöver vi egentligen filer i våra program? Tre huvudsakliga
anledningar:

\begin{enumerate}
\item \textbf{Persistens}: Filer låter oss \emph{minnas} data mellan olika
  körningar av programmet. Om vi skriver ett program som samlar in data från
  användaren vill vi kanske spara den informationen så att den finns kvar
  nästa gång programmet körs.

\item \textbf{Datautbyte}: Filer låter oss \emph{överföra} data mellan olika
  program. Ett program kan generera data och spara i en fil, som sedan kan
  läsas av ett annat program. Detta är grunden för hur program samarbetar.

\item \textbf{Skalbarhet}: Filer låter oss hantera \emph{stora mängder} data
  som inte får plats i primärminnet samtidigt. Vi kan läsa och bearbeta data
  bit för bit från en fil istället för att behöva ha allt i minnet på en gång.
\end{enumerate}

\begin{frame}
  \begin{remark}
    \begin{itemize}
      \item Behövs för att minnas mellan körningarna.
      \item Behövs för att överföra data mellan program.
      \item Behövs för att hantera kopiösa mängder data.
    \end{itemize}
  \end{remark}
\end{frame}


\section{Hur använder vi filer?}

\ltnote{%
  \textbf{LO}: \FilesLOOperations*, \FilesLOContextMgr*, \FilesLOFileTypes*.

  \textbf{Generalisering + Kontrast}: Koppling till \mintinline{python}{print()}/
  \mintinline{python}{input()}. Samma princip (strukturera data för I/O),
  olika destination. Filer kräver explicit öppning/stängning.

  \textbf{Variationsmönster}:
  \begin{description}
    \item[Kontrast] \mintinline{python}{open()}/\mintinline{python}{close()} vs
      \mintinline{python}{with} (resurshante ring).
    \item[Separation] Läsa vs skriva, text vs binär.
  \end{description}

  \textbf{Sekvens}: Dokumentation $\to$ manuell öppning/stängning $\to$
  \mintinline{python}{with} $\to$ läsa/skriva $\to$ filtyper.
}

Nu när vi förstår \emph{varför} filer behövs är det dags att lära oss \emph{hur} vi använder dem i Python. Det viktiga att komma ihåg är att filhantering bygger på samma princip som vi redan känner från \mintinline{python}{print()} och \mintinline{python}{input()}: att strukturera data för ett specifikt syfte.

När vi använde \mintinline{python}{print()} skrev vi till terminalen; när vi använde \mintinline{python}{input()} läste vi från terminalen. Nu ska vi lära oss att skriva till och läsa från filer istället. Principen är densamma --- endast destinationen ändras.

\subsection{Öppna och stänga}

Innan vi kan arbeta med en fil måste vi \emph{öppna} den. Detta ger oss ett filobjekt som vi kan använda för att läsa eller skriva data. När vi är färdiga måste vi också \emph{stänga} filen för att frigöra systemresurser och säkerställa att all data verkligen skrivs till disken.

Det finns två sätt att hantera öppning och stängning: manuellt med \mintinline{python}{open()} och \mintinline{python}{close()}, eller automatiskt med \mintinline{python}{with}-satsen. Låt oss först titta på den manuella metoden för att förstå vad som egentligen händer, sedan ska vi se varför \mintinline{python}{with}-satsen är det bättre alternativet.

\ltnote{%
  \textbf{Kontrast}: Resurshanteringsmetod (manuell
  \mintinline{python}{open()}/\mintinline{python}{close()} vs
  \mintinline{python}{with}). Invariant: Filoperationerna.

  \textbf{Kritiska aspekter}:
  \begin{itemize}
    \item \textbf{\FilesLOOperations* --- Resurshantering}: Filer måste stängas.
    \item \textbf{\FilesLOContextMgr*}: \mintinline{python}{with} garanterar
      automatisk stängning även vid fel.
  \end{itemize}

  \textbf{Sekvens}: Visa explicit metod först (synlig resurshantering),
  sedan \mintinline{python}{with} (abstraktion).
}

  \begin{minted}[numbers=none,fontsize=\Large]{python}

print(file.read())
file.close()
  \end{minted}
\end{frame}

\begin{frame}[fragile]

  \end{example}

Som vi ser i exemplen ovan fungerar båda metoderna. Men \mintinline{python}{with}-satsen har en avgörande fördel: den garanterar att filen \emph{alltid} stängs korrekt, även om ett fel uppstår i programmet. Med den manuella metoden riskerar vi att lämna filen öppen om något går fel mellan \mintinline{python}{open()} och \mintinline{python}{close()}.

Därför rekommenderas starkt att använda \mintinline{python}{with}-satsen för all filhantering. Det är säkrare, tydligare, och tar hand om resurshanteringen automatiskt.

\subsection{Läsa och skriva}

Nu när vi vet hur vi öppnar och stänger filer ska vi titta på de grundläggande operationerna: att läsa data från en fil och att skriva data till en fil. Precis som \mintinline{python}{input()} läser från terminalen och \mintinline{python}{print()} skriver till terminalen, används \mintinline{python}{file.read()} för att läsa från en fil och \mintinline{python}{file.write()} för att skriva till en fil.

När vi öppnar en fil måste vi ange ett \emph{läge} som talar om vad vi vill göra:
\begin{itemize}
  \item \mintinline{python}{"r"} för läsning (\foreignlanguage{english}{read}),
  \item \mintinline{python}{"w"} för skrivning 
    (\foreignlanguage{english}{write}), eller
  \item \mintinline{python}{"a"} för att lägga till i slutet 
    (\foreignlanguage{english}{append}).
\end{itemize}
Läget avgör vilka operationer som är tillåtna på filen.

\ltnote{%
  \textbf{Separation + Generalisering}: Operation (read vs write), filläge
  (\mintinline{python}{"r"} vs \mintinline{python}{"w"}). Invariant:
  Filhanteringsmönster (öppna-operera-stäng).

  \textbf{Kritisk aspekt (\FilesLOOperations*)}: Läsning och skrivning är
  motsatta operationer, samma mönster.

  \textbf{Flera läsmetoder}: \mintinline{python}{file.read()} vs
  \mintinline{python}{for line in file} (olika granularitet, samma princip).

  \textbf{Sekvens}: Skrivning först, sedan läsning (ger data att läsa).
}

När vi skriver till en fil använder vi \mintinline{python}{file.write()}, som fungerar nästan som \mintinline{python}{print()}, men med en viktig skillnad: \mintinline{python}{write()} lägger \emph{inte} till radbrytningar automatiskt. Om vi vill ha radbrytningar måste vi själva lägga till \mintinline{python}{'\n'}.

När vi läser från en fil kan vi antingen använda \mintinline{python}{file.read()} för att läsa hela innehållet som en enda sträng, eller iterera över filen rad för rad med en \mintinline{python}{for}-loop. Den senare metoden är ofta mer minneseffektiv för stora filer eftersom vi inte behöver ladda allt i minnet samtidigt.

\subsection{Typer av filer}

Hittills har vi arbetat med textfiler --- filer som innehåller läsbar text. Men inte alla filer är textfiler. Bilder, videor, och komprimerade filer är exempel på \emph{binärfiler} som innehåller data i ett format som inte är direkt läsbart som text.

Python skiljer mellan dessa två typer av filer, och vi måste ange rätt läge när vi öppnar dem. För textfiler använder vi lägena \mintinline{python}{"r"}, \mintinline{python}{"w"}, och \mintinline{python}{"a"}. För binärfiler lägger vi till ett \mintinline{python}{"b"}: \mintinline{python}{"rb"}, \mintinline{python}{"wb"}, \mintinline{python}{"ab"}.

\ltnote{%
  \textbf{Kontrast}: Filtyp (text vs binär), struktur (radbrytningar vs rå bytes).
  Invariant: Filhanteringsoperationer.

  \textbf{Kritiska aspekter (\FilesLOFileTypes*)}:
  \begin{itemize}
    \item Textfiler: Läsbara tecken, struktur (kod, CSV).
    \item Binärfiler: Rå bytes (bilder, video).
    \item Lägesval: \mintinline{python}{"r"}/\mintinline{python}{"w"} vs
      \mintinline{python}{"rb"}/\mintinline{python}{"wb"}.
  \end{itemize}

  \textbf{Referensbild}: Dokumentation visar alla lägen som verktyg.
}

\begin{frame}
  \begin{remark}[Två typer av filer]
    \begin{description}
      \item[Textfiler] Antar \enquote{läsbara tecken}, rader bryts med 
        \mintinline{python}{'\n'}.
      \item[Binärfiler] Ingen struktur.
    \end{description}
  \end{remark}
\end{frame}

\section{Filformat}

\ltnote{%
  \textbf{LO}: \FilesLOCSV*.

  \textbf{Generalisering + Kontrast}: Komplexitetsnivå av filformat (eget
  $\to$ CSV). Invariant: Strukturera data.

  \textbf{Kritiska aspekter (\FilesLOCSV*)}:
  \begin{itemize}
    \item Struktureringsprincipen: Filer kräver format (som
      \mintinline{python}{print()} kräver formatering).
    \item CSV är STANDARD (robustare än egen parsing).
    \item \mintinline{python}{csv}-modulen hanterar edge cases automatiskt.
  \end{itemize}

  \textbf{Sekvens}: Metafor (\enquote{bäcksvarta mörkret}) $\to$ SCB-exempel
  $\to$ eget format (xy.py) $\to$ CSV-dokumentation $\to$ CSV-implementation.
}

Att kunna läsa och skriva filer är en sak, men \emph{hur} ska vi strukturera informationen i filerna? Detta är en fundamental fråga som vi måste besvara varje gång vi arbetar med filer. Det räcker inte att bara kunna öppna och stänga --- vi måste också veta hur data är organiserad.

Tänk dig att du får en textfil med tusentals rader text. Var finns telefonnumren? Var finns adresserna? Vilka delar hör ihop? Utan en tydlig struktur är det som att gå i bäcksvarta mörkret --- vi vet inte var vi ska leta efter informationen vi behöver.

Detta problem löser vi med \emph{filformat}: överenskommelser om hur data ska organiseras i en fil. Ett filformat är som ett kontrakt mellan programmet som skriver filen och programmet som läser den. Båda måste förstå samma struktur för att kommunikationen ska fungera.

\subsection{Mer komplexa standarder}

Istället för att uppfinna egna format för vanliga behov är det mycket bättre att använda \emph{standardformat} --- välkända och väl testade format som många program förstår. Ett av de vanligaste formaten för tabelldata är CSV (\foreignlanguage{english}{Comma-Separated Values}).

\begin{frame}

Fördelen med att använda denna modul istället för att själv dela upp strängar vid kommatecken är att CSV-modulen hanterar alla specialfall korrekt: citattecken, kommatecken inuti fält, olika radbrytningar, och så vidare.

\begin{frame}[fragile]
  \begin{example}[xy\textunderscore csv.py]

Den viktigaste lärdomen här är att \emph{formatering och struktur är lika viktigt för filer som för terminalutskrift}. Precis som vi måste tänka på hur vi formaterar output med \mintinline{python}{print()}, måste vi tänka på hur vi strukturerar data i filer. Skillnaden är att för filer finns det ofta etablerade standarder vi kan använda, vilket gör våra program mer kompatibla och robusta.
